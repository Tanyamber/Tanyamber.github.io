CASE STUDY

UK Financial Transactions Data Pipeline

A cloud-native ELT pipeline ingesting live transactional JSON from a public REST API into Google BigQuery, using PyArrow for efficient in-memory handling and GCP IAM for secure credentials, reported through Power BI.

View on GitHub

Executive Summary

Financial reporting often depends on data trapped in operational systems with no direct reporting layer. This project built a live, cloud-native ingestion pipeline that pulls transactional data straight from a REST API into a BigQuery warehouse, ready for Power BI reporting — no manual exports required.

Business Problem

Manually exporting and reshaping transactional data for reporting is slow, error-prone and doesn't scale. The goal was a repeatable, automated path from a live API straight into an analytics-ready warehouse.

Solution Architecture

Public REST API (JSON)
        │
        ▼
 Python + PyArrow (in-memory processing)
        │
        ▼
 GCP IAM (service-account credentials)
        │
        ▼
 Google BigQuery (warehouse)
        │
        ▼
 Power BI Reporting Layer

Technology Stack

Python • PyArrow • REST API • Google BigQuery • GCP IAM • Power BI

Pipeline Stages

  1. Call the public REST API to pull live transactional JSON.
  2. Process records in memory with PyArrow for efficient type handling.
  3. Authenticate securely to Google Cloud using a GCP IAM service account.
  4. Load curated records into a BigQuery warehouse table.
  5. Connect Power BI directly to BigQuery for reporting.

Engineering Considerations

  • Service-account based credential security via GCP IAM, avoiding hard-coded secrets.
  • PyArrow used for memory-efficient, typed in-memory data handling ahead of load.
  • BigQuery chosen as a serverless warehouse to avoid infrastructure management.

Dashboard Focus

Transaction Volume

Live view of transaction throughput as new records land in BigQuery.

Data Freshness

Pipeline designed around live ingestion rather than static batch exports.

Secure Access

Credential handling via GCP IAM service accounts rather than static keys.

Reporting Layer

Power BI connects directly to BigQuery, keeping one source of truth.

Business Benefits

  • Removes manual export/reshape steps from financial reporting.
  • Serverless warehouse means no infrastructure to manage or patch.
  • Reusable ingestion pattern for any REST-based data source.

Key Learning

This project strengthened practical skills in cloud-native ELT design, GCP IAM security, and PyArrow-based data handling — extending the ETL discipline I built in banking onto a fully serverless cloud stack.
