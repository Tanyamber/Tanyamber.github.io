CASE STUDY

Hospitality EPOS Data Pipeline

A production-style enterprise data platform processing 50,000 synthetic EPOS transactions across restaurants, pubs and hotels: Python → Azure SQL → Azure Data Factory → Snowflake → dbt Cloud → Power BI DirectQuery.

View on GitHub

Executive Summary

Hospitality groups run point-of-sale data across many disconnected venues. This project built an end-to-end scalable platform that generates realistic EPOS data, lands it in Azure SQL, moves it through Azure Data Factory into Snowflake, transforms it in dbt Cloud, and reports on it live through Power BI DirectQuery — following the same data-engineering best practices used in production environments.

Business Problem

Multi-venue hospitality businesses need a single, trustworthy view of venue performance and guest loyalty, but data usually starts scattered across separate EPOS systems with no shared model or governance.

Technology Stack

Python • Azure SQL • Azure Data Factory • Snowflake • dbt Cloud • Power BI (DirectQuery)

Engineering Highlights

  • Configured Snowflake Storage Integration with Azure IAM role assignment, plus full RBAC (ownership transfer from ACCOUNTADMIN to SYSADMIN) — eliminating token-based authentication.
  • Built a 3-tier dbt transformation layer: a staging view for type validation and field standardisation, an ephemeral intermediate CTE using ROW_NUMBER and LAG window functions for customer visit sequencing, and materialised mart tables.
  • Implemented 30/90/180-day loyalty thresholds feeding a 2,000-customer retention and CLV forecast model.
  • Custom generate_schema_name dbt macro override for schema routing, with dbt documentation generated for every model.
  • 5 of 5 automated dbt schema tests passing.
  • Version control via dev/main Git branching with a conventional-commit PR merge workflow, plus an engineering journal documenting technical decisions and troubleshooting.

Key Learning
